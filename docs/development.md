# Developing styleck

## Design

Each rule is the single source of truth for its prose instruction and its
detector. `claude.md` is generated from the registry, preventing the guide and
the checker from drifting apart.

Errors block an agent or pre-commit hook. Warnings are advisory. Rules that
require human judgment appear in the generated guide but have no detector.

## Share the writing guide across repositories

Each paper repository can keep its own workflow instructions while importing
the generated writing guide:

```sh
python -m styleck --sync ~/research
python -m styleck --sync ~/research --add-import
```

The second command also adds `@writing-style.md` to each repository's
`claude.md`. A `writing-style.md` not generated by styleck is never
overwritten.

## Add a rule

Write a detector in `styleck/rules_tex.py` or `styleck/rules_prose.py`:

```python
@register(
    id="eq-trailing-punct",
    section="Equations",
    severity=ERROR,
    applies_to=TEX,
    summary="Put no punctuation at the end of a display equation.",
    bad="\\[ x = y . \\]",
    good="\\[ x = y \\]",
)
def check_eq_trailing_punct(document): ...
```

The generated guide includes it on the next `styleck --docs`. Add a rule with
no reliable detector to `styleck/rules_manual.py` via `manual(...)`; the guide
tags it **judgment**, and the checker never reports it.

To make a rule auto-fixable, add an entry to `FIXERS` in
`styleck/fixers.py`. The fuzz tests then require the repair to be idempotent,
to preserve words, and to leave no violation of that rule behind.

## Tests

```sh
python -m unittest discover -s tests
```

`test_fuzz.py` checks generated and malformed LaTeX, scanner coverage, and
fixer idempotence. The test suite also verifies that the generated guide is
synchronized with the registry.
